# 同城社区便民服务平台 MVP 开发总控 Prompt

你现在要作为一名资深微信小程序全栈工程师，帮助我开发一个“同城社区便民综合服务平台”的 MVP 版本。

我已经完成了 MVP 功能规划，你需要严格围绕 MVP 范围进行开发，不要擅自扩展复杂功能。项目目标不是一次性做完整商业平台，而是先跑通核心业务闭环：

8. 不为了快速实现而破坏架构

## 五、订单状态机要求

请统一使用明确的订单状态枚举，不要在代码里随意写中文状态。

订单状态建议如下：

```js
const ORDER_STATUS = {
  PENDING_PAY: 'pending_pay',           // 待付款
  PENDING_ACCEPT: 'pending_accept',     // 待接单
  ACCEPTED: 'accepted',                 // 已接单
  SERVING: 'serving',                   // 服务中
  PENDING_REVIEW: 'pending_review',     // 待评价
  COMPLETED: 'completed',               // 已完成
  CANCELED: 'canceled'                  // 已取消
}
```

支付状态建议如下：

```js
const PAY_STATUS = {
  UNPAID: 'unpaid',
  PAID: 'paid'
}
```

订单状态流转必须集中管理，不能在多个页面中随便修改订单状态。

建议封装统一方法，例如：

* createOrder
* mockPayOrder
* cancelOrder
* acceptOrder
* startService
* finishService
* createReviewAndCompleteOrder
* adminUpdateOrderStatus

必须校验当前状态是否合法。

例如：

* 只有 pending_pay 可以模拟支付
* 只有 pending_accept 可以接单
* 只有 accepted 可以开始服务
* 只有 serving 可以完成服务
* 只有 pending_review 可以评价
* 只有 pending_pay 和 pending_accept 可以取消

## 六、角色权限要求

系统包含三类角色：

```js
const USER_ROLE = {
  USER: 'user',
  WORKER: 'worker',
  ADMIN: 'admin'
}
```

权限要求：

### 普通用户

普通用户可以：

* 浏览服务
* 创建订单
* 模拟支付自己的订单
* 查看自己的订单
* 取消自己的订单
* 评价自己的订单
* 管理自己的地址
* 申请成为师傅

普通用户不能：

* 查看他人订单
* 接单
* 审核师傅
* 管理服务
* 修改订单状态

### 师傅

师傅可以：

* 查看符合条件的待接单订单
* 接单
* 查看自己接到的订单
* 开始服务
* 完成服务
* 查看自己的收入统计

师傅不能：

* 查看无关订单
* 修改服务项目
* 审核其他师傅
* 修改他人订单
* 修改用户信息

### 管理员

管理员可以：

* 管理服务分类
* 管理服务项目
* 审核师傅
* 查看所有订单
* 查看所有用户
* 查看所有师傅
* 查看基础统计数据
* 手动调整订单状态，主要用于调试和管理

请将权限校验放在云函数或统一业务层中，不要只依赖前端按钮隐藏。

## 十一、代码质量要求

请严格遵守以下代码质量要求：

1. 所有状态、角色、错误码必须使用常量，不要写魔法字符串。
2. 所有云函数返回格式统一，例如：

```js
{
  success: true,
  data: {},
  message: 'success'
}
```

失败时：

```js
{
  success: false,
  errorCode: 'ORDER_STATUS_INVALID',
  message: '当前订单状态不允许执行该操作'
}
```

3. 页面中不要直接写复杂业务逻辑。
4. 数据库操作要尽量封装。
5. 订单状态修改必须校验权限和当前状态。
6. 管理员操作必须校验管理员角色。
7. 师傅接单必须校验师傅审核状态。
8. 用户只能操作自己的订单。
9. 师傅只能操作自己接到的订单。
10. 页面表单必须有基础校验。
11. 按钮操作要防止重复点击。
12. 列表页要考虑空状态和加载状态。
13. 所有时间字段统一命名。
14. 所有金额字段统一使用 number 类型，单位为元或分需要提前说明并保持一致。
15. 重要函数需要写简洁注释。
16. 代码风格保持统一。
17. 不要把所有逻辑写在 app.js。
18. 不要让一个文件过长，必要时拆分。
19. 不要出现重复代码，通用逻辑应抽取工具函数或组件。
20. 后续能方便接入真实支付、分佣、合伙人、地图定位和 PC 后台。

# 同城社区便民综合服务平台 MVP 开发清单

## 1. 项目定位

本项目是一个面向同城社区便民服务场景的微信小程序 MVP 版本，核心目标是跑通基础业务闭环：

> 居民用户选择服务并下单 → 师傅接单 → 师傅完成服务 → 用户确认与评价 → 管理员查看和管理订单

第一版不追求完整商业化能力，而是优先完成小程序开发练手所需的核心模块，包括多角色登录、服务展示、订单流转、师傅接单、评价、管理员审核与基础管理。

## 5. 推荐技术方案

## 5.1 推荐方案 A：微信小程序原生 + 云开发

适合作为练手 MVP。

### 前端

* [ ] 微信原生小程序
* [ ] WXML
* [ ] WXSS
* [ ] JavaScript
* [ ] 小程序组件化开发

### 后端

* [ ] 微信云开发
* [ ] 云数据库
* [ ] 云函数
* [ ] 云存储

### 优点

* [ ] 不需要单独购买服务器
* [ ] 登录接入简单
* [ ] 适合快速开发 MVP
* [ ] 部署成本低
* [ ] 方便练习小程序完整流程

---

## 5.2 推荐方案 B：微信小程序 + Node.js + MySQL

适合后期升级为正式项目。

### 前端

* [ ] 微信原生小程序

### 后端

* [ ] Node.js
* [ ] NestJS 或 Express
* [ ] MySQL
* [ ] Redis，选做
* [ ] 对象存储，选做

### 优点

* [ ] 更接近真实商业项目
* [ ] 权限系统更灵活
* [ ] 后期容易做 PC 后台
* [ ] 更适合写进简历或作品集

### 当前建议

第一版 MVP 建议优先使用：

> 微信小程序原生 + 云开发

等业务流程跑通后，再考虑重构为：

> 小程序 + 独立后端 + PC 管理后台

## 9. 订单状态流转设计

## 9.1 用户下单流程

```text
用户选择服务
↓
填写地址、预约时间、备注
↓
提交订单
↓
订单状态：待付款 pending_pay
↓
模拟支付
↓
订单状态：待接单 pending_accept
```

---

## 9.2 师傅接单流程

```text
订单状态：待接单 pending_accept
↓
师傅点击接单
↓
绑定 worker_id
↓
订单状态：已接单 accepted
```

---

## 9.3 服务执行流程

```text
订单状态：已接单 accepted
↓
师傅点击开始服务
↓
订单状态：服务中 serving
↓
师傅点击完成服务
↓
订单状态：待评价 pending_review
```

---

## 9.4 用户评价流程

```text
订单状态：待评价 pending_review
↓
用户提交评分与评价
↓
生成评价记录
↓
订单状态：已完成 completed
```

---

## 9.5 取消订单流程

第一版只允许以下状态取消：

* [ ] 待付款
* [ ] 待接单

```text
待付款 / 待接单
↓
用户取消订单
↓
订单状态：已取消 canceled
```

暂不处理：

* [ ] 已接单后取消
* [ ] 服务中取消
* [ ] 退款
* [ ] 售后仲裁

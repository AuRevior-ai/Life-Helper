# 微信支付开通与真机联调操作文件

本文用于指导当前小程序 MVP 开通微信支付并准备真实小额支付联调。请按顺序执行。完成本文后，把“需要回填给开发”的信息提供给开发侧，再进入真实支付代码联调。

## 1. 操作目标

本次只完成微信支付开通与联调准备：

- 确认小程序主体和商户号具备支付能力。
- 将商户号绑定到当前小程序 AppID。
- 开通 JSAPI 支付权限。
- 准备 APIv3 密钥、商户 API 私钥和商户 API 证书序列号。
- 准备支付回调地址 `notify_url`。
- 准备低金额真机支付测试条件。

当前工程已经完成模拟支付、支付日志、售后申请和模拟退款。真实支付开通完成后，再补齐真实微信支付签名、下单、回调验签和小额联调。

## 2. 重要边界

- 小程序支付场景按微信支付官方说明使用 JSAPI 支付权限。
- 不要把 APIv3 密钥、商户私钥、证书文件、真实订单导出提交到 Git。
- 不要在小程序前端写入商户密钥。
- 第一轮只测小额支付，不测真实退款。
- 当前退款仍为模拟退款，真实退款等支付跑通后再接入。

## 3. 准备账号

需要准备以下登录账号和权限：

| 平台 | 地址 | 需要权限 |
| --- | --- | --- |
| 微信公众平台 | `https://mp.weixin.qq.com/` | 小程序管理员或开发者权限 |
| 微信支付商户平台 | `https://pay.weixin.qq.com/` | 商户号超级管理员或具备产品中心、账户中心权限的操作员 |
| 微信开发者工具 | 本地工具 | 可打开当前项目并选择云开发环境 |

建议让商户号超级管理员在旁边配合，因为 APIv3 密钥和商户 API 证书通常需要较高权限。

## 4. 确认小程序已认证

1. 登录微信公众平台。
2. 进入当前小程序。
3. 查看小程序基本信息和认证状态。
4. 确认主体已完成微信认证。
5. 记录小程序 AppID。

小程序 AppID 查看路径：

```text
微信公众平台 -> 开发与服务 -> 开发管理 -> 开发设置 -> AppID(小程序ID)
```

记录：

```text
小程序 AppID：
小程序名称：
小程序主体：
```

如果小程序未认证，先完成小程序认证；未认证会影响支付能力开通和真机支付。

## 5. 准备或申请微信支付商户号

### 5.1 已有商户号

1. 登录微信支付商户平台。
2. 确认当前商户号可正常登录。
3. 记录商户号。
4. 确认商户主体与小程序主体是否一致。

记录：

```text
商户号 mchid：
商户简称：
商户主体：
与小程序主体是否一致：
```

### 5.2 没有商户号

1. 进入微信支付商户平台。
2. 按商户入驻流程申请新商户号。
3. 入驻时选择小程序支付相关场景。
4. 填写当前小程序 AppID。
5. 完成资料提交和审核。

新商户号申请完成后，通常会对填写的 AppID 发起授权绑定。仍需按第 6 节检查绑定状态。

## 6. 绑定商户号与小程序 AppID

### 6.1 在商户平台查看已绑定 AppID

1. 登录微信支付商户平台。
2. 进入：

```text
产品中心 -> APPID账号管理 -> 我关联的APPID账号
```

3. 检查当前小程序 AppID 是否已在列表中。

记录：

```text
AppID 是否已绑定：
绑定状态：
绑定发起时间：
是否需要审核：
```

### 6.2 发起绑定申请

如果 AppID 未绑定：

1. 在商户平台进入：

```text
产品中心 -> APPID账号管理
```

2. 选择新增或绑定新的 AppID。
3. 填写当前小程序 AppID。
4. 阅读并勾选授权协议。
5. 提交绑定申请。
6. 如平台要求小程序侧确认，登录微信公众平台完成授权确认。

注意：

- 一个商户号可关联多个 AppID，但不要绑定错 AppID。
- 如果小程序主体与商户主体不一致，平台可能要求补充主体信息或进入审核。
- 绑定关系建立后通常不建议随意更换。

## 7. 开通 JSAPI 支付权限

1. 登录微信支付商户平台。
2. 进入：

```text
产品中心 -> JSAPI支付
```

3. 查看 JSAPI 支付状态。
4. 如果未开通，点击“申请开通”。
5. 按页面要求补充经营信息、场景说明、截图或材料。
6. 提交申请。
7. 等待审核。

记录：

```text
JSAPI 支付状态：
申请提交时间：
预计/实际审核通过时间：
是否有驳回原因：
```

审核通过后再次进入：

```text
产品中心 -> JSAPI支付
```

确认状态为已开通或可用。

## 8. 配置 APIv3 密钥

APIv3 密钥用于微信支付 APIv3 回调报文解密等安全场景，属于高敏感信息。

1. 使用商户号超级管理员登录微信支付商户平台。
2. 进入：

```text
账户中心 -> 账户设置 -> API安全 -> APIv3密钥
```

3. 如果没有 APIv3 密钥，按页面提示设置。
4. 密钥长度要求为 32 个字符，通常由数字、大小写字母组成。
5. 设置后立即保存到安全的私密位置。

记录时不要把明文写入仓库。只记录是否已准备：

```text
APIv3 密钥是否已设置：
密钥保管人：
设置日期：
```

需要回填给开发侧时，使用私密渠道提供，不要发到公开聊天、Git、截图或文档仓库。

## 9. 申请商户 API 证书并获取私钥

商户 API 证书用于 APIv3 请求签名。真实 JSAPI 下单需要用商户私钥生成签名。

1. 使用商户号超级管理员登录微信支付商户平台。
2. 进入：

```text
账户中心 -> 账户设置 -> API安全 -> 商户API证书
```

3. 点击申请或管理证书。
4. 按页面提示下载证书工具。
5. 使用证书工具生成申请文件。
6. 上传申请文件。
7. 下载证书文件。
8. 在本地证书目录中找到商户私钥文件，通常是：

```text
apiclient_key.pem
```

9. 在商户平台页面查看并记录商户 API 证书序列号。

记录：

```text
商户 API 证书是否已申请：
证书序列号 merchantSerialNo：
apiclient_key.pem 是否已安全保存：
证书保管人：
证书申请日期：
```

注意：

- `apiclient_key.pem` 是敏感私钥文件，不要提交仓库。
- 不要截图私钥内容。
- 不要发到群聊。
- 不要放到小程序前端目录。

## 10. 准备支付回调 notify_url

微信支付成功后会向 `notify_url` 发送异步通知。真实支付必须准备一个微信支付可以公网访问的 HTTPS 地址。

当前工程后端逻辑入口是：

```text
cloudfunctions/payment
action: handlePayNotify
```

你需要准备以下二选一方案。

### 10.1 推荐方案：云函数 HTTP 触发路径

如果当前云开发环境支持给 `payment` 云函数配置 HTTP 访问服务：

1. 打开微信开发者工具或云开发控制台。
2. 进入云开发环境。
3. 找到云函数 `payment`。
4. 配置 HTTP 访问服务或 HTTP 触发路径。
5. 确认外部 HTTPS 地址可访问。
6. 将该地址作为支付回调 `notify_url`。

记录：

```text
notify_url：
对应云环境 ID：
对应云函数：
是否公网 HTTPS：
是否已测试可访问：
```

### 10.2 备选方案：自有 HTTPS 服务转发

如果云函数 HTTP 触发路径暂时不可用：

1. 准备一个自有 HTTPS 服务。
2. 接收微信支付回调原始请求。
3. 保留请求头和请求体。
4. 转发给云函数 `payment.handlePayNotify` 或在自有服务内完成验签和业务处理。

记录：

```text
自有服务域名：
转发路径：
SSL 证书状态：
负责人：
```

## 11. 准备小额测试条件

1. 准备一个普通用户微信号，用于真实支付。
2. 该微信号需要能登录当前小程序。
3. 准备一个测试服务项目和测试地址。
4. 准备小额支付金额，建议：

```text
0.01 元
```

如果微信支付或商户平台对最低金额、行业、测试账号有限制，以平台当前提示为准。

记录：

```text
测试微信号：
测试用户 openid：
测试金额：
测试服务：
测试时间窗口：
```

## 13. 开发侧收到信息后的工作

开发侧会继续完成：

1. 将小程序端支付模式从 `mock` 切换为 `wechat`。
2. 在云函数安全环境中配置商户资料。
3. 补齐真实 JSAPI 下单请求签名。
4. 生成 `wx.requestPayment` 所需参数。
5. 补齐支付回调验签和报文解密。
6. 真实支付成功后更新订单为待接单。
7. 写入 `payment_logs`。
8. 保持重复回调幂等。
9. 执行 0.01 元小额真机支付测试。

## 14. 小额支付验收清单

真实支付联调完成后，按以下标准验收：

- [ ] 小程序可在真机登录。
- [ ] 普通用户可创建测试订单。
- [ ] 点击支付可以拉起微信支付收银台。
- [ ] 支付金额与订单后端金额一致。
- [ ] 支付成功后微信支付产生交易单号。
- [ ] `payment_logs` 写入创建支付日志。
- [ ] `payment_logs` 写入支付回调日志。
- [ ] 订单状态变为 `pending_accept`。
- [ ] 师傅接单大厅能看到该订单。
- [ ] 重复支付同一订单被拦截。
- [ ] 重复回调不会重复发消息或重复改状态。
- [ ] 订单可以继续完成接单、服务、评价闭环。

## 15. 常见问题排查

### 15.1 无法拉起支付

优先检查：

- 小程序 AppID 是否真实。
- 商户号是否绑定该 AppID。
- JSAPI 支付是否已开通。
- 下单时传入的 appid 是否与当前小程序一致。
- 下单时传入的 mchid 是否与绑定商户号一致。
- 前端支付参数签名是否使用同一个 appid 和 prepay_id。

### 15.2 返回 AppID 与商户号不匹配

优先检查：

- 商户平台 `APPID账号管理` 是否已有该小程序 AppID。
- 当前云函数配置的 mchid 是否是绑定该 AppID 的商户号。
- 是否误用了测试号、游客 AppID 或其他小程序 AppID。

### 15.3 回调没有到达

优先检查：

- `notify_url` 是否是公网 HTTPS。
- 云函数 HTTP 触发路径是否启用。
- 回调路径是否能被外网访问。
- 微信支付平台是否有回调失败记录。
- 云函数日志是否有请求记录。

### 15.4 订单没有变为待接单

优先检查：

- `payment_logs` 是否有回调日志。
- 回调金额是否与订单金额一致。
- `out_trade_no` 是否能找到订单。
- 回调验签是否失败。
- 订单是否已经被取消或已支付。

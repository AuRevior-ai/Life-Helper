# 决策：当前阶段仅使用 mock 支付

日期：2026-06-10

## 背景

当前工程已经跑通用户下单、mock 支付、服务方接单、服务完成、评价、售后 mock 退款、内部模拟财务流水和管理员管理等 MVP 闭环。真实微信支付、真实退款、提现、分账、真实保证金支付和真实现金流仍需要营业执照、商户号、证书、密钥、回调验签、退款接口、对账和专项真机验证。

## 决策

当前及后续普通功能开发阶段继续只使用 mock 支付、mock 退款和内部模拟财务流水，不考虑接入真实支付现金流。

后续 Agent 评价当前工程时，不得仅因未接入真实微信支付、真实退款、提现、分账或真实现金流，将工程判定为 P0 阻塞。

## 正确评价口径

以下情况不应列为当前 P0：

- 未配置真实微信支付商户号、APIv3 密钥或证书。
- 未完成真实微信支付小额测试。
- 未完成真实微信退款小额测试。
- 财务流水来自 mock 支付和内部模拟记录。
- `PAY_MODE=wechat` 仍是占位入口并 fail-fast。

以下情况仍应按 P0 或高风险问题处理：

- 当前阶段明确要求进入真实支付、退款、提现、分账或正式商用资金闭环，但代码未完成。
- 页面、文档或代码把 mock 支付、模拟退款、内部模拟流水包装成真实资金能力。
- 支付成功、退款成功、订单完成、收益结算、财务流水生成等关键状态可被前端伪造或越权修改。
- 真实密钥、证书、商户号、支付配置、真实 openid、真实交易数据进入仓库或交付包。
- 发布候选包风险扫描失败。

## 后续条件阶段

如果未来重新决定接入真实支付现金流，必须另起独立高风险阶段，并至少补齐：

- JSAPI 下单。
- 请求签名和前端支付参数签名。
- 支付回调验签。
- 退款和退款回调。
- 对账或异常补偿方案。
- 敏感配置注入与发布包脱敏检查。
- 专项自动化测试和小额真机验证。
- 回滚与降级方案。

在该条件阶段启动前，当前工程以 mock 支付闭环为验收标准。

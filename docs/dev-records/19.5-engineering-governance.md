# 阶段 19.5：工程治理、结构修复与交付风险收口

## 阶段背景

项目已完成到阶段 19：商家端与店铺主页基础版，业务闭环已经覆盖用户端、师傅端、商家端、管理员端、订单、mock 支付、售后退款、评价、消息、财务、优惠券、打赏和商家入驻。继续直接进入阶段 20 会把保证金、资质认证和风控叠加到已有技术债上，因此本阶段先做工程治理。

## 为什么不能直接进入阶段 20

阶段 20 涉及身份证、营业执照、资质、保险、保证金和风控审核，权限、状态、数据库字段和资金边界都会更复杂。当前已存在公共工具重复、状态常量重复、API action 缺少统一清单、数据库 schema 缺失、权限矩阵缺失、README 与 AppID 不一致、mock 支付边界不够醒目等问题。若继续堆功能，后续 AI Agent 很容易复制旧模式并扩大维护成本。

## 公共工具抽取说明

已抽取低风险、稳定且重复最多的函数：`success`、`fail`、`serviceError`、`getPayload`、`getNow`、`paginateList`。分页工具支持 `listKey`，用于保留 `message` 云函数的 `messages` 和 `tip` 云函数的 `tips` 兼容字段。不抽取 `requireOpenid`、`requireAdmin`，因为各云函数错误语义和账号状态判断存在差异。

## 状态契约整理说明

`status-contract.md` 覆盖订单、支付、售后、退款、会员、收益、服务方类型和商家状态。当前前端 `miniprogram/config/status.js` 作为展示权威来源，云函数局部常量通过测试约束核心状态一致性。未引入自动生成机制，避免扩大改动面。

## 数据库 schema 整理说明

`database-schema.md` 覆盖 `users`、`orders`、`workers`、`merchants`、`merchant_services`、`service_providers`、`reviews`、`messages`、`payment_logs`、`refund_logs`、`finance_logs`、`worker_earnings`、优惠券/会员、打赏、售后退款以及其他日志集合。无法从当前代码完全确认的字段已标注“待核实”。

## API action 清单整理说明

`api-actions.md` 基于当前 handler 的 `actions` 映射整理，覆盖 `login`、`user`、`service`、`address`、`order`、`worker`、`review`、`admin`、`message`、`payment`、`refund`、`area`、`dispatch`、`finance`、`promotion`、`tip`、`merchant`。发现 `mockPayOrder` 与 `payment.createPayment` 并存、`getWorkerReviews` 与 `getWorkerReviewList` 语义接近，但本阶段只记录，不合并。

## 权限矩阵整理说明

`permission-matrix.md` 按游客、普通用户、师傅、商家、管理员和系统内部调用整理。明确用户私有数据、师傅订单、商家订单、管理员接口、支付退款财务、mock 资金能力和幂等边界。当前记录的 P1 风险包括真实支付回调验签未接入、商家收益/评价细粒度权限后续需增强。

## 交付风险收口说明

`.git` 不删除开发者本地目录，但正式交付包必须排除。真实 AppID 不擅自删除，README 已说明 `project.config.json` 是内部开发配置，公开交付应使用 `project.config.example.json`。交付风险扫描脚本可对候选目录执行检查。

## mock 支付边界说明

当前是 mock 支付、mock 退款、mock 打赏、mock 会员开通和 mock 解冻；无真实扣款、无真实退款、无真实分账、无真实提现。财务流水仅验证业务流程，不代表微信支付清算。真实上线仍需商户号、JSAPI 权限、APIv3 密钥、证书、回调验签、退款接口、对账流程和小额真机测试。

## 商家端体验说明

商家端当前重点是业务流程验证，不是最终运营级 UI。商家中心等页面仍偏基础入口形态。后续建议单独安排“商家端体验增强阶段”，不要在阶段 20 保证金/资质模块中顺手大改 UI。

## 测试结果

本阶段新增治理测试后运行 `npm test`。最终测试结果以本次交付输出为准。新增测试覆盖共享响应工具、分页工具、状态一致性、契约文档存在与非空、交付风险扫描、README 与 AppID/mock 支付一致性。

## 未完全修复的问题

- 大 handler 尚未拆分，只完成盘点和低风险共享工具接入。
- `requireOpenid`、`requireAdmin` 尚未统一抽取。
- 状态常量尚未改成自动生成或前后端共享构建。
- 数据库 schema 文档仍需真实云数据库字段和索引回填。
- 真实支付、真实退款、真实分账、真实提现仍未接入。
- 商家端运营级 UI 和细粒度商家评价/收益权限仍需后续阶段处理。

## 后续 AI Agent 硬性约束

1. 不允许复制 `success`、`fail`、`serviceError`、`getPayload`、`getNow`、`paginateList`，新云函数必须优先使用 `_shared`。
2. 新增状态必须同步 `status-contract.md`、前端状态常量、后端常量和测试。
3. 新增集合字段必须同步 `database-schema.md`。
4. 新增 action 必须同步 `api-actions.md`。
5. 新增权限边界必须同步 `permission-matrix.md`。
6. 新增业务阶段必须写阶段复盘并更新 `docs/dev-records/index.md`。
7. 每阶段必须运行 `npm test`。
8. 不允许把 mock 支付、mock 退款、mock 打赏、mock 财务描述成真实生产能力。
9. 每 3-5 个功能阶段必须插入一次工程治理阶段。

## 阶段结论

阶段 19.5 完成后，可以进入阶段 20，但阶段 20 必须继续使用 mock 保证金能力，不得接入真实支付，不得顺手重做商家 UI，不得新增未记录的状态、字段或 action。进入阶段 20 前仍建议先阅读本文件、四份 contracts 文档和 release checklist。

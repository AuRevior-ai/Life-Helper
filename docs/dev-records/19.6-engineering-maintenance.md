1. release 风险扫描脚本不可靠：已修复 `scripts/check-release-risk.js`。目录不存在时返回非 0 并提示“待扫描目录不存在”；默认未传参时扫描当前工程；正常 `docs/**/*.md`、`tests/**/*.test.js`、`*.example.*`、mock/example 占位文件不再误报；`.env`、`project.private.config.json`、`*.pem`、`*.key`、日志、压缩包、真实密钥内容仍会拦截。
2. AppID 测试硬编码：已更新 `tests/phase19_5.engineering-governance.test.js` 和 `tests/phase19_6.engineering-maintenance.test.js`，测试动态读取 `project.config.json`，不再硬编码历史 AppID。
3. 真实微信支付半实现误用风险：已更新 `cloudfunctions/payment/wechat-pay-client.js`，`PAY_MODE=wechat` 但真实支付未实现时抛出 `WECHAT_PAY_NOT_IMPLEMENTED`，不返回空 `prepay_id` 或空 `payParams`。README 与 `docs/wechat-pay-setup.md` 已同步说明。
4. `_shared` 公共工具接入不足：已接入 `order`、`admin`、`finance`、`refund`、`review`、`worker`、`promotion`、`dispatch`、`area`、`service`、`user`、`login`。仅接入 `success`、`fail`、`serviceError`、`getPayload`、`getNow`、`paginateList` 等低风险工具，未统一业务权限函数。
5. 云函数依赖版本不统一：已将 `area`、`dispatch`、`merchant`、`tip` 的 `wx-server-sdk` 从 `3.0.1` 统一到多数版本 `3.0.4`，新增 `scripts/check-cloudfunction-deps.js` 和测试约束。
6. 数据库 schema 缺少机器契约：新增 `schema/*.schema.json` 初版，覆盖 `orders`、`users`、`merchants`、`service_providers`、`finance_logs`、`worker_earnings`、`payment_logs`、`refund_logs`。
7. API action 清单缺少机器约束：新增 `docs/contracts/api-actions.manifest.json`，按云函数列出当前 handler 已存在 action，并由测试检查 manifest action 名称出现在 handler 中。
8. 分页和索引风险未系统记录：新增 `docs/contracts/pagination-and-indexes.md`，记录 list 类 action、分页支持、全量读取、内存过滤、推荐索引、最大 pageSize 和改造优先级。
9. 大 handler 后续拆分计划不清：本阶段不做大拆，只在本文件记录后续拆分建议。
10. 商家端基础验证版边界不清：README 和本文件明确商家端当前适合流程验证，不等于正式运营级商家后台。

## 共享工具接入复盘

已接入共享工具的云函数：

- `address`、`merchant`、`message`、`payment`、`tip`：阶段 19.5 已接入。
- `order`、`admin`、`finance`、`refund`、`review`、`worker`、`promotion`、`dispatch`、`area`、`service`、`user`、`login`：阶段 19.6 新增接入。

未接入或未统一的内容：

- `requireOpenid`、`requireAdmin`、`requireCurrentUser`、`requireMerchant`、`requireWorker` 等权限函数仍保留在本地 handler。
- 未统一原因：这些函数涉及角色、订单归属、商家归属、管理员初始化、师傅审核等业务语义，强行抽取可能改变权限边界。
- 后续建议：在新增权限矩阵测试和更细粒度 contract 后，再按云函数族逐步统一。

本阶段不大规模移动业务代码。后续可按以下方向拆分：

```text
order:
  order-create.service.js
  order-pay.service.js
  order-worker.service.js
  order-cancel.service.js
  order-status-machine.js
  order-validator.js
  order-repository.js

merchant:
  merchant-apply.service.js
  merchant-admin.service.js
  merchant-store.service.js
  merchant-order.service.js
  merchant-service-item.service.js
  merchant-log.service.js

finance:
  finance-log.service.js
  worker-earning.service.js
  merchant-income.service.js
  finance-summary.service.js
```

建议拆分顺序：先拆纯校验、状态机、repository adapter，再拆服务层；每次拆分必须保持 action 名称、返回格式和页面调用不变。

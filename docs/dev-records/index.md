# 完整项目开发路线图（从 MVP 到完整平台）

> 规划依据：当前已完成阶段 0-15 与修复收口；目标依据 background 中的完整 PRD、思维导图与“五端完整平台”要求。  
> 当前定位：MVP 与试运营前核心能力已完成，后续开发从“可用 MVP”进入“完整商业平台化”。

## 1. 当前完成度定位

| 口径 | 当前状态 | 估算完成度 |
|---|---|---:|
| MVP 核心闭环 | 已完成并完成多轮修复收口 | 95%+ |
| 小范围试运营版本 | 仍需补齐财务、区域、营销、资质、合伙人基础能力 | 55%-65% |
| 完整 PRD 五端平台 | 用户端、服务端、合伙人端、城市端、PC后台、分佣结算、AI仍未完全实现 | 40%-45% |
| 商用可招商版本 | 真实支付、分佣、提现、PC后台、合伙人、多城市、风控合规仍需建设 | 30%-40% |

---

## 2. 后续开发总原则

1. 不推倒重写，沿用现有 `miniprogram / cloudfunctions / docs / tests` 模块化结构。
2. 每阶段必须新增对应 `docs/dev-records/XX_xxx.md` 并更新本 `index.md`。
3. 每阶段必须补充测试文件或更新既有测试，保证 `npm test` 全部通过。
4. 真实微信支付、真实退款、真实提现、分账能力受营业执照和商户号限制，暂列为“条件阶段”，先保留 mock 与 adapter。
5. 资金、分佣、提现、合伙人、PC后台属于高权重高风险模块，必须拆阶段开发。
6. 所有资金相关动作必须有流水、日志、幂等校验、权限校验和回冲机制。
7. 所有平台规则必须优先配置化，不要硬编码到页面。
8. 业务核心流程优先级高于 UI 美化和 AI 增强。
9. 完整项目开发顺序建议遵循：财务基础 → 营销基础 → 评价打赏 → 入驻资质 → LBS派单 → 合伙人 → 分佣结算 → PC后台 → 真实支付联调 → AI与风控。

## 4. 各阶段开发计划详情

### 阶段 16：财务流水与服务方收益基础版

目标：建立基础账务结构，让订单从“服务闭环”升级为“交易闭环”。

核心功能：
- 新增 `finance_logs` 财务流水集合。
- 新增 `worker_earnings` 服务方收益集合。
- 订单完成后生成服务方收益记录。
- 支持平台固定抽佣比例，先 mock 配置。
- 支持收益状态：冻结中、可结算、已结算、已回冲。
- 售后退款后自动回冲未结算收益。
- 师傅端展示收益明细、冻结金额、可结算金额。
- 管理端展示订单财务流水。

关键要求：
- 不做真实提现。
- 不做合伙人分佣。
- 不做自动打款。
- 所有金额以后端订单金额为准。
- 财务流水必须幂等，不能重复生成。

## 2. 本阶段目标

本阶段先改用户端首页，而不是一次性改全站 UI。首页是用户第一次理解平台定位的入口，适合作为后续视觉基线；同时只改首页可以避免订单、支付、退款、财务、派单、商家、资质、保证金和 LBS 等核心业务在 UI 阶段被误触。

## 6. 首页新版结构说明

首页新版结构包含顶部问候、当前位置胶囊、搜索入口、社区便民服务 Banner、服务分类卡片、常用服务卡片和底部保障条。

搜索框与“查看更多”跳转服务列表页。分类项继续携带 `categoryId` 跳转服务列表页。常用服务行和“立即预约”按钮跳转服务详情页。

## 7. 视觉规范说明

首页使用浅灰页面背景、白色大圆角卡片、社区绿色主色、暖橙价格、柔和阴影和较大的垂直留白。按钮使用 `999rpx` 胶囊圆角。图标和图片均为纯 WXSS 占位，不使用在线图片、不引入第三方 UI 框架或图标库。

## 8. 组件变化说明

本阶段未新增公共组件，也未修改现有 `service-card`、`worker-card`、`status-tag`、`empty-state`、`loading-view` 等公共组件。首页展示结构直接落在 `pages/index`，避免样式影响其它页面。

## 9. 业务保护说明

本阶段未修改云函数、数据库结构、订单状态机、支付、退款、财务、派单、资质、保证金、LBS、商家和服务端核心逻辑。首页仍通过 `service.service.js` 调用已有 `getCategoryList` 和 `getServiceList`。

## 10. TabBar 处理说明

当前项目使用 `app.json` 原生 tabBar，不是 `custom-tab-bar`。本阶段不强行切换自定义 tabBar，只在首页增加底部安全留白，避免内容被原生 tabBar 遮挡。参考图中的圆角浮层底部导航留到后续全局 UI 阶段统一处理。

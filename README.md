# 同城社区便民综合服务平台 MVP

这是一个基于微信原生小程序和微信云开发的同城社区便民服务平台 MVP。第一版目标是跑通核心业务闭环：用户下单、模拟支付、师傅接单、开始服务、完成服务、用户评价、管理员查看和管理数据。

## 阶段二说明

登录与用户体系使用 `users` 集合。第一版头像昵称使用默认值，手机号只保留字段，后续在地址或下单阶段再强制填写。

管理员初始化已迁移到身份选择页的管理员端初始化流程，并增加云函数环境变量保护。真实环境默认不允许初始化首个管理员，需显式设置 `ADMIN_BOOTSTRAP_ENABLED=true`，并建议配置 `ADMIN_BOOTSTRAP_ALLOWED_OPENIDS` 限定 openid；如配置 `ADMIN_BOOTSTRAP_CODE`，调用方还需传入初始化码。

微信开发者工具登录跑通步骤见：[docs/wechat-login-runbook.md](docs/wechat-login-runbook.md)。

完整验证清单见：[docs/wechat-mvp-verification.md](docs/wechat-mvp-verification.md)。

真实环境问题记录见：[docs/wechat-real-env-issues.md](docs/wechat-real-env-issues.md)。

发布包提交检查见：[docs/release-package-checklist.md](docs/release-package-checklist.md)。

微信支付接入说明见：[docs/wechat-pay-setup.md](docs/wechat-pay-setup.md)。

当前支持模拟支付、模拟退款、内部模拟财务流水、模拟会员开通、优惠券抵扣和模拟打赏；真实微信支付、真实微信退款、真实打赏支付需要营业执照、商户号、证书、密钥和回调地址。本阶段继续使用 mock 支付模式，不接入真实地图定位、提现、真实分账、真实会员支付、真实打赏支付、会员自动续费、合伙人结算和真实财务对账。商家端当前不支持连锁商家、多门店、商家员工排班和真实商家分账。金额字段统一使用“分”，订单最终金额以后端计算为准，一笔订单最多使用一张优惠券，退款后优惠券默认不退回。评价隐藏会保留历史记录，不做物理删除。

## 云开发说明

小程序入口使用 `wx.cloud.DYNAMIC_CURRENT_ENV` 初始化云环境。创建真实云开发环境后，可在微信开发者工具中选择对应环境并部署云函数。

阶段二验证建议：

1. 创建 `users` 集合
2. 上传并部署 `cloudfunctions/login`
3. 上传并部署 `cloudfunctions/user`
4. 编译小程序
5. 进入“我的”页面
6. 点击“微信授权登录”
7. 打开云数据库 `users` 集合，确认用户记录存在

阶段三验证建议：

1. 上传并部署 `cloudfunctions/service`
2. 编译小程序
3. 首页查看服务分类和推荐服务
4. 点击分类进入服务列表
5. 点击服务卡片进入服务详情

阶段四验证建议：

1. 创建 `addresses` 集合
2. 创建 `orders` 集合
3. 上传并部署 `cloudfunctions/address`
4. 上传并部署 `cloudfunctions/order`
5. 确认 `login`、`user`、`service` 云函数也已部署
6. 编译小程序并完成微信授权登录
7. 在“我的 - 地址管理”新增默认地址
8. 从服务详情点击“立即预约”
9. 填写预约时间并提交订单
10. 在订单详情点击“模拟支付”
11. 回到“我的订单”，确认订单状态为“待接单”

阶段五验证建议：

1. 创建 `workers` 集合
2. 上传并部署 `cloudfunctions/worker`
3. 重新上传并部署 `cloudfunctions/order`
4. 确认 `login`、`user`、`service`、`address` 云函数也已部署
5. 用户完成微信授权登录并提交师傅入驻申请
6. 在云数据库 `users` 集合中将管理员账号 `role` 改为 `admin`
7. 管理员进入师傅审核页，通过师傅申请
8. 用户侧创建订单并完成模拟支付，让订单进入“待接单”
9. 已审核师傅进入接单大厅并点击接单
10. 进入师傅订单列表，确认订单状态为“已接单”

阶段六验证建议：

1. 创建 `reviews` 集合
2. 上传并部署 `cloudfunctions/review`
3. 重新上传并部署 `cloudfunctions/order`
4. 确认 `login`、`user`、`service`、`address`、`worker` 云函数也已部署
5. 用户创建订单并完成模拟支付
6. 已审核师傅接单
7. 师傅进入订单详情并点击“开始服务”
8. 师傅点击“完成服务”

10. 用户提交评分和评价内容
11. 用户订单状态应变为“已完成”
12. 师傅进入收入统计页，确认累计收入包含该订单
